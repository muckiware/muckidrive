# Upgrading a muckidrive project

A muckidrive project consists of two parts:

- **Packages** (`muckiware/core`, `muckiware/master`, `shopware/core`, ...) - updated with Composer.
- **Project files** (`public/index.php`, `bin/console`, `bin/build-*.sh`, `.htaccess` files, `config/bundles.php`, `.env`, `.gitignore` blocks, `custom/*` placeholders) - generated by [Symfony Flex recipes](https://symfony.com/doc/current/setup/flex.html) and updated with `composer recipes:update`.

The muckidrive recipes are served from the [muckiware/recipes](https://github.com/muckiware/recipes) endpoint. It must be the **first** entry in `extra.symfony.endpoint` of your `composer.json`, because Flex uses the first endpoint that lists a package (muckidrive overrides the `shopware/core` recipe with an empty one):

```json
"extra": {
    "symfony": {
        "allow-contrib": true,
        "endpoint": [
            "https://raw.githubusercontent.com/muckiware/recipes/flex/main/index.json",
            "https://raw.githubusercontent.com/shopware/recipes/flex/main/index.json",
            "flex://defaults"
        ]
    }
}
```

Projects created with `composer create-project muckiware/muckidrive` from the first release after v0.1.4 on already contain this setting.

## Regular update

Recipe updates are applied as a 3-way merge, so the project must be a **git repository with a clean working tree** (commit or stash your changes first).

```bash
# 1. Update the packages
composer update

# 2. Show which recipes have updates
composer recipes

# 3. Apply the recipe updates
composer recipes:update muckiware/core
composer recipes:update muckiware/master

# 4. Review, resolve conflicts (if any) and commit
git diff
git commit -am "chore: update muckidrive recipes"
```

`composer recipes:update` without a package name lets you pick each outdated recipe interactively.

## One-time migration of projects created from v0.1.0 - v0.1.4

Projects created from v0.1.0 to v0.1.4 have the `shopware/core` recipe from `shopware/recipes` in their `symfony.lock` and no muckiware recipes at all. Migrate them once:

1. Make sure the project is a git repository with a clean working tree.
2. Add `https://raw.githubusercontent.com/muckiware/recipes/flex/main/index.json` as the **first** entry of `extra.symfony.endpoint` in `composer.json` (see above).
3. Update the muckiware packages:

   ```bash
   composer update "muckiware/*" -W
   ```

4. Install the muckidrive recipes, then replace the Shopware recipe with the empty muckidrive override:

   ```bash
   composer recipes:install muckiware/core muckiware/master symfony/mcp-bundle --force --reset
   composer recipes:install shopware/core --force --reset
   ```

5. Review the changes with `git diff`. `--force --reset` **overwrites** the recipe files with the recipe versions, so local customisations (e.g. in `public/index.php` or `.htaccess`) are lost - re-apply them before committing. Check in particular that `config/bundles.php` still contains no `Shopware\Core\Checkout\Checkout` and no `Shopware\Core\Framework\Framework`.
6. Commit the result. From now on, use the [regular update](#regular-update).

> `composer recipes:update shopware/core` fails on such a project with a harmless HTTP 404: the old Shopware recipe reference stored in `symfony.lock` does not exist in the muckiware recipe archive. Use the `recipes:install` commands from step 4 instead.
